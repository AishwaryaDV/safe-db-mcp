> Our own working brief, extracted from the Oct 26, 2026 handoff doc. This is the single
> source of truth we execute against for Project A. Project B (`sec-filings-qa`) is tracked

## 1. One-line pitch

An MCP server that lets an AI client (Claude Desktop / Cursor) query **SQLite** databases
**safely** — every query validated, limited, and logged — plus an eval harness that measures
how accurately a model answers benchmark questions **through** the server's tools.

Portfolio project, not a product. Framing: "built to learn how production database MCP
servers handle safety, and to measure model accuracy through one." **Never** call it new,
first, or the only one of anything.

## 3. Shared conventions (apply to A; `llm_client.py` is later copied to B)

### Stack / tooling
- Python 3.11+, `pyproject.toml`, `ruff` (lint + format), `pytest`, type hints everywhere,
  `pydantic` models for every tool input, tool output, and API body.
- Backend: **FastAPI**. Frontend: **Next.js** (App Router, TypeScript) + Tailwind, in `web/`.
- Config: `config.yaml` for non-secrets, `.env` for secrets, committed `.env.example`,
  loaded with `pydantic-settings`.
- `Makefile` targets: `setup`, `test`, `eval`, `run`, `lint`.
- Structured JSON logs. **MIT licence.** Never commit `data/raw`, `.env`, or databases.
- **No LangChain / LlamaIndex / similar frameworks.**

### `llm_client.py` contract (write carefully here, copy to B)

```python
class LLMResult(BaseModel):
    text: str | None
    tool_calls: list[ToolCall]   # name + arguments
    usage: Usage                 # input_tokens, output_tokens
    latency_ms: int
    backend: str                 # claude_sdk | gemini
    model: str
    cached: bool

class LLMClient:
    def generate(self, messages, tools=None, response_schema=None, temperature=0.0) -> LLMResult: ...
```

- **Backends** (choose via `LLM_BACKEND`):
  - `claude_sdk` — development only; owner's local Claude Code login via the Claude Agent
    SDK, no API credits.
  - `gemini` — free tier, key in `GEMINI_API_KEY`.
- **Fallback:** if `claude_sdk` raises / is unavailable, retry once on `gemini`, log it.
- **Modes** (`LLM_MODE`): `live` (call model), `record` (call + save), `replay` (read cache
  only; a cache miss raises an error saying to re-record). **CI always runs `replay`.**
- **Cache key:** SHA-256 of model name, messages, tool definitions, response schema,
  temperature. Cache files in `llm_cache/`; commit only files needed by the baseline run.
- **Quota guard:** count requests/day in `llm_calls`; refuse new live calls above
  `DAILY_LLM_BUDGET` (default 200) with a clear error. Keep budget below the conservative
  Gemini figure; check current docs.
- **Call log:** every call writes a row to `llm_calls` (time, backend, model, latency,
  input + output tokens, cached, error, run id).
- **Tool calling:** translate the neutral `tools` list into each backend's function-calling
  format *inside* the client; the rest of the code only sees the neutral list.

### Tests + CI (GitHub Actions)
- Pytest markers: `unit`, `integration`, `live_llm`. CI runs everything **except** `live_llm`.
- Jobs: lint; unit + integration tests; repo-specific gate (safety tests); eval in `replay`
  with a regression check.
- Manual `workflow_dispatch` job runs a small live smoke test using the `GEMINI_API_KEY`
  secret.
- **Regression gate:** fail the build if the main score drops **> 3 points** below the
  committed `eval/baseline.json`, or on any cache miss.

## 6. MCP tool contracts

Official **Python MCP SDK**, transport **stdio**, entry point `safedb-mcp --config config.yaml`.
Confirm the SDK's current API before writing `server.py`. Server makes **no LLM calls**, has
**no write tools**, returns plain data (structured content **and** a text rendering).

### `list_databases`
- In: none → Out: `{databases: [{name, description, table_count}]}`

### `describe_schema`
- In: `{database: str, table?: str, sample_rows?: int (0–5, default 3)}`
- Out: `{database, tables: [{name, row_count, columns: [{name, type, primary_key, not_null}],
  foreign_keys: [{column, ref_table, ref_column}], sample_rows: [[...]]}]}`
- Sample cells > 80 chars → ellipsis. `sample_rows=0` omits the field.

### `run_query`
- In: `{database: str, sql: str, max_rows?: int}`
- Success: `{ok: true, columns, rows, row_count, truncated, elapsed_ms}`
- Failure: `{ok: false, error_type, message, hint?}`
- `max_rows` default 100, capped at `max_rows_cap`. Cells > `max_cell_chars` cut.

### `explain_query`
- In: `{database: str, sql: str}`
- Out: `{ok: true, plan: [str]}` or the same failure shape. Same validation; **never executed**.

### Error types
| `error_type` | When | Hint |
| --- | --- | --- |
| `blocked` | Validation rejected the SQL | "one SELECT statement only" |
| `syntax` | Parser / SQLite syntax error | parser message + position |
| `unknown_object` | Unknown db / table / column | up to 3 closest real names (difflib); for a table, its columns |
| `timeout` | Ran longer than `timeout_s` | suggest filters / LIMIT / simpler joins |
| `too_large` | SQL longer than `max_sql_chars` | suggest shorter query |
| `internal` | Anything else | none; log exception, generic message |

With `HINTS=off` (eval experiment): return **only** `message`.

### Resource
`schema://{database}` → full schema as markdown (tables, columns, keys).

### Prompt
`analyst` with arg `database`. Short working rules: call `describe_schema` before writing
SQL; quote identifiers that need it; always limit rows; state assumptions; if ambiguous ask
**one** clarifying question instead of guessing; never attempt to change data.

### Tool descriptions
All description strings live in `tool_descriptions.py`. Each ≤ 3 sentences, says when to use
the tool. **Record a hash of this file in every eval run** (wording affects accuracy).

## 7. Safety layer (build as independent layers, in order)

Confirm exact API names in Python `sqlite3` and `sqlglot` docs first.

1. **Size check** — reject if longer than `max_sql_chars` (`too_large`).
2. **Parse** — `sqlglot`, SQLite dialect. Parse failure → `syntax`.
3. **Exactly one statement** — more than one → `blocked`.
4. **Allow-list the statement** — root must be `SELECT` (incl. `WITH ... SELECT`, set ops
   like `UNION`). Walk the tree; reject any non-read node (command, pragma, attach, insert,
   update, delete, create, drop, alter, vacuum).
5. **Deny dangerous functions** by name — at minimum `load_extension`, `readfile`,
   `writefile`, `edit`.
6. **Read-only connection** — open with `file:` URI + `mode=ro`, then `PRAGMA query_only = ON`.
   Disable extension loading.
7. **Authorizer** — register a callback allowing only read actions (select, read, permitted
   functions, recursive); deny everything else. Second wall behind the parser.
8. **Timeout** — progress handler checking a monotonic clock every ~1000 VM steps; abort
   after `timeout_s`; map abort → `timeout`.
9. **Row + cell caps** — fetch `max_rows + 1`, return `max_rows`, set `truncated`. Cut long
   cells.
10. **One connection per call**, closed afterwards. One in-flight query per database.
11. **Audit** — write the audit row on a separate writable connection, in a `finally` block,
    so blocked and failed calls are logged too.

Also unit-test: the **authorizer alone** denies a write when `validate_sql` is bypassed
(call executor with the parser check stubbed out).

## 8. Audit log & API

### `audit_log` (in `audit.sqlite`, separate from every data DB)
```sql
CREATE TABLE audit_log (
  id INTEGER PRIMARY KEY,
  ts TEXT NOT NULL,           -- ISO 8601 UTC
  source TEXT NOT NULL,       -- mcp | api | eval
  tool TEXT NOT NULL,         -- list_databases | describe_schema | run_query | explain_query
  database TEXT,
  sql TEXT,
  sql_hash TEXT,
  status TEXT NOT NULL,       -- ok | blocked | error | timeout
  error_type TEXT,
  reason TEXT,
  row_count INTEGER,
  truncated INTEGER,
  elapsed_ms INTEGER,
  run_id TEXT                 -- set for eval runs
);
CREATE INDEX audit_ts ON audit_log (ts);
CREATE INDEX audit_status ON audit_log (status);
```
The `llm_calls` table lives in the same file.

### API (FastAPI) — browser input **never** contains raw SQL
| Endpoint | Purpose |
| --- | --- |
| `GET /api/health` | Liveness |
| `GET /api/audit?status=&database=&limit=&before_id=` | Paged audit rows, newest first |
| `GET /api/eval/runs` | List runs with config + headline metrics |
| `GET /api/eval/runs/{run_id}` | Full metrics for one run |
| `GET /api/eval/runs/{run_id}/questions?result=` | Per-question records, filter match/mismatch |
| `GET /api/examples` | Cached example questions + recorded answers |
| `POST /api/ask` `{database, question}` | Runs `agent.py`; SSE: `tool_call`, `tool_result`, `final` |

**Limits on `/api/ask`:** 10 requests/visitor/day (by IP hash); global daily cap below the
LLM budget; cached answers for example questions. On cap hit → HTTP 429 + friendly message +
example answers.

## 10. Eval harness

### Commands
- `python -m eval.build_slice` — pick 50 questions (fixed seed), compute gold, write `slice.jsonl`.
- `python -m eval.run_eval --split tune|holdout --config eval/configs/baseline.yaml --mode live|record|replay`
- `python -m eval.score --run <run_id>` — recompute metrics from a saved run.
- `python -m eval.compare` — one comparison table from `run.json` files.

### Agent loop (`agent.py`)
1. Start the MCP server as a subprocess; connect with the Python MCP client over stdio.
2. List the server's tools; convert to `llm_client` tool format.
3. Fetch the `analyst` prompt via MCP; use as system prompt with the db name filled in.
4. Send the question. Loop: if the model calls a tool, forward via MCP client, append result;
   stop when the model replies with no tool call **or after 5 tool calls**.
5. Final SQL = the last `run_query` that returned `ok: true`. If none → fail with reason
   `no_successful_query`.
6. Temperature 0. Never include `gold_sql` / `gold_result` anywhere in the conversation.

### Per-question record (`results/<run_id>/questions.jsonl`)
```json
{"id": "q007", "steps": [{"tool": "run_query", "args": {}, "ok": false, "error_type": "unknown_object"}], "final_sql": "...", "match": true, "first_try_valid": false, "recovered": true, "blocked_count": 0, "tool_calls": 3, "latency_ms": 4120, "tokens_in": 2210, "tokens_out": 180, "backend": "gemini", "model": "..."}
```
### Run record (`results/<run_id>/run.json`)
config, split, seed, git SHA, hash of `tool_descriptions.py`, backend + model, date, headline
metrics.

### Metrics
| Metric | Definition |
| --- | --- |
| Execution accuracy | matches / questions |
| First-try valid rate | questions whose first `run_query` returned `ok: true` / questions |
| Recovery rate | questions with a failed first query that ended in a match / questions with a failed first query |
| Blocked-query rate | blocked attempts / all `run_query` attempts |
| Tool calls & latency | mean + 95th percentile |
| Tokens | mean input + output per question |

Also report accuracy by difficulty.

### Experiments (each a config file; run on `tune`, confirm once on `holdout`)
1. `sample_rows`: 3 vs 0 in `describe_schema`
2. `hints`: on vs off in error responses

### Ambiguity set
Run `ambiguity.jsonl` through the same loop; save transcripts. Owner scores each good/bad in
`ambiguity_scores.csv`; a script reports counts.

### Free-tier budget
Before a live/record run, print max requests it could use (questions × 6) and remaining daily
budget. Refuse to start if it would exceed budget unless `--force`. Every live response cached.

### Replay & CI
Baseline run's cache + `eval/baseline.json` committed. CI runs `--mode replay` on `tune`;
fails if accuracy is > 3 points below baseline, or on a cache miss (message must say to
re-record). Replay reproduces recorded metrics exactly.

## 14. How A connects to B

- Build **A first**: it gives the shared plumbing (`llm_client.py`, replay/cache, call log,
  eval pattern, regression gate, tune/holdout split, caps, README standard) plus MCP
  experience reused in B's optional MCP server.
- `llm_client.py` is written carefully here and **copied** into B.
- A's extra step is **M1b related-work research** (B has none). A's eval measures whether SQL
  results match known answers; B's measures retrieval + answer correctness + refusals.
